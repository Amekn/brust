# Atomic Writes and Strict BAM Reading Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add crash-safe, fsync'd atomic file output to every brust writer, and an opt-in strict
EOF-block check for BAM input, then move the facade and CLI onto both.

**Architecture:** One `brust_core::AtomicFile` (a buffered `Write` sink: temp file beside the
target, commit = flush, fsync, close, rename, folder fsync; delete on drop). Each format crate
adds an `impl Writer<AtomicFile>` block with `from_path_atomic`/`commit`, and each in-memory
type adds `to_path_atomic`. `BgzfReader`/`BamReader` gain `set_require_eof_block`. The facade's
`convert`, `validate` and `stats` use both, and the private `write_atomic` goes away.

**Tech Stack:** Rust 2024 workspace (rust-version 1.96), std only for the new code, flate2
(already used by `brust-fastq` and `brust-bam`).

**Spec:** `docs/superpowers/specs/2026-10-01-atomic-io-design.md` (approved 01/10/2026).
Read it alongside this plan.

## Global Constraints

- No new dependencies or dev-dependencies in any crate. `brust-core` stays dependency-free.
- Existing format-crate behaviour is unchanged: `from_path`, `new`, `from_writer`, `to_path`,
  `from_reader`, `Bam::from_path` and `Bam::from_reader` behave exactly as today.
- Temp file name: `.{pid}.{counter}.tmp.{file_name}` in the target's parent (`.` when the path
  has no parent part), opened with `create_new(true)`, at most 100 tries.
- `commit` order: flush the buffer → `sync_all` the temp file → close it → `fs::rename` →
  (Unix only) open the parent folder and `sync_all` it.
  - Closing is unchecked, because std ignores close errors and the data is already synced.
  - The new file is published at the rename. A folder-sync error after that is reported, but
    the file stays in place.
- Strict BAM error: built with the crate's `invalid_data`, so it is
  `io::ErrorKind::InvalidData` and carries a BAM diagnostic, and the facade sees
  `error.format() == Some(Format::Bam)`. The diagnostic message is exactly
  `BGZF stream ended without the EOF block; the file may be truncated`, and `to_string()` is
  `invalid BAM: ` followed by that message. It is reported once. After it, the reader behaves
  as at end of stream, as it already does after other truncation errors.
- Every workspace crate ends at version `0.3.0` (Task 6 only).
- New test files outside `brust/tests` hand-roll temp folders, as existing tests do. Each
  defines:
  - a `TempDir` like `brust/tests/common/mod.rs`: a unique folder under
    `std::env::temp_dir()` named with the crate, test name, pid and a counter, removed on drop,
    with `join(&str) -> PathBuf` and `path() -> &Path`;
  - `fn names(dir: &Path) -> Vec<String>`, returning the folder's sorted file names.

  Test code below uses `dir.join(..)` and `names(dir.path())` for these.
- In `brust/tests`, reuse `common::TempDir` unchanged. Adding helpers there would leave them
  unused in some test binaries, and `-D warnings` would fail. List a folder with
  `names(&temp.join("."))`, as `brust/tests/convert.rs:423` does, with `names` defined locally
  in each test file that needs it.
- New docs and messages use NZ English spelling (e.g. "behaviour"). Don't respell existing text.
- Each commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A bare relative output path** (`brust convert … out.fasta` run from the output's folder).
   The temp file must go in `.`, and the output must appear with nothing left behind. Tested
   in Task 5 (`cli_convert_accepts_bare_relative_output`).
2. **Non-ASCII, spaced or upper-case gzip target names** (`réads 1.FQ.GZ`). Gzip selection and
   the temp name must work from the target name. Tested in Task 3
   (`atomic_gzip_detection_uses_target_name`).
3. **A read-only existing target.** `File::create` fails on it today, but `rename` replaces it,
   as `convert` and `mv` already do. This is a deliberate choice, so Task 1 pins it
   (`commit_replaces_read_only_target`, Unix) and documents it with the known limits.
4. **Dropping a threaded `BamWriter<AtomicFile>` without commit.** The workers must stop, and no
   temp file may remain. Tested in Task 3 (`dropped_threaded_writer_leaves_nothing`).
5. **Strict mode through `records()` and `read_all()`.** A truncated BAM must give `Err`, not a
   shorter `Vec`, and `records()` must end after that one error instead of repeating it forever.
   Tested in Task 4 (`strict_error_surfaces_through_records_and_read_all` and
   `strict_error_is_reported_once`).

- [ ] **Step 3: Implement `AtomicFile` in `brust-core/src/atomic_file.rs`**
  - **Fields:** `writer: Option<BufWriter<File>>` (std default capacity), the temp path, the
    target path, and `published: bool`, which is set only once the rename succeeds.
  - **`Drop` is the single cleanup path**, and `commit(self)` relies on it: any early `?` return
    drops `self`.
    - If `writer` is still `Some`, discard the buffer without flushing (`BufWriter::into_parts`)
      and close the file.
    - If `!published`, remove the temp file.
    - Ignore every error.
  - **Temp names:** a private `static TEMP_COUNTER: AtomicU64` numbers them.
  - **`create` errors:**
    - no file name: `InvalidInput`, message `output path {path} must include a file name`;
    - 100 names taken: `AlreadyExists`, message `could not create temporary output beside {path}`;
    - any other open error is returned unchanged.
  - **`commit`:** runs the Global Constraints order and returns the first error from flush,
    `sync_all` or rename. `Drop` then removes the temp file.
    - Flush failure: split `BufWriter::into_inner`'s `IntoInnerError` with `into_parts()`, then
      the returned `BufWriter` with `BufWriter::into_parts()`, so the failed buffer is never
      flushed again. `IntoInnerError::into_error()` would drop the `BufWriter`, and its `Drop`
      flushes.
    - After the rename, set `published = true`.
    - A failure opening **or** syncing the Unix parent folder returns
      `io::Error::new(original_kind, "renamed {target} into place but syncing folder {parent} failed: {error}")`.
  - **Rustdoc for the type:**
    - the commit order;
    - that the new contents appear at the target only when `commit` reaches the rename, and
      that `commit` can return an error after that point (folder sync) with the new file
      already in place;
    - that other platforms skip the folder sync;
    - the spec's known limits, plus Review Focus 3 (a read-only target is replaced).
